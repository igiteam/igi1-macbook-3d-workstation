🎯 What You Can Actually Run

With that much hardware, you're not just running Forgejo. You could run:

  • 35 separate Forgejo instances — one per project, fully isolated, each with its own LFS store
  • A Kubernetes cluster — 35 nodes is enough for a serious k3s or k8s lab
  • A CI/CD farm — each Pi runs one Forgejo runner; parallel builds across 35 nodes
  • A distributed database — CockroachDB, Cassandra, or ScyllaDB across 35 nodes
  • A rendering farm — if you ever do 3D or video work
  • A game server cluster — PufferPanel on each, one game server per node
  • A monitoring stack — Prometheus + Grafana scraping all 35 nodes
  • A honeypot network — 35 isolated nodes for security research

The WineJS platform you've been building would scale beautifully across this. Each Pi could host a different set of Windows apps, and the translator could route between them.

⚠️ The Real Challenges at 35 Nodes

The math is compelling, but there are practical issues that only show up at scale.

1. Rack, Power, and Cooling

  • 35 Pis in a rack need a proper 19" rack enclosure with shelves or DIN rails. That's £200–£500.
  • Power: 35 × 27W PSUs = ~945W peak. You need a UPS and probably a dedicated circuit. A decent 1500VA UPS is £200–£400.
  • Cooling: 35 Pis in a closed rack will get hot. You need rack fans or an open-frame rack. Budget £100–£300.
  • Network: You need a 48-port gigabit switch (~£150–£400) and enough power outlets (a rack PDU, ~£100–£200).

2. Management Overhead

Managing 35 separate Pis by hand is painful. You'd want:

  • Ansible (or similar) to push configs to all 35 at once
  • A monitoring stack (Prometheus + Grafana + node_exporter) to see which ones are down
  • Centralized logging (Loki or similar) so you're not SSHing into each one
  • A container registry so you build once and deploy everywhere

3. Physical Space

35 Pis + rack + UPS + switch + PDU is roughly the size of a small mini-fridge. You need a dedicated corner, closet, or rack.

4. Failure Rate

At 35 nodes, you will have failures. SD cards die, PSUs fail, fans seize. You need:

  • Spare Pis on hand (buy 2–3 extras)
  • A rebuild process that's fully automated (this is where your first-boot SD card idea pays off)
  • Monitoring that alerts you when a node goes down

💡 The Smarter Alternative (If You Don't Need Physical Units)

If the goal is compute, not hardware ownership, consider:

  • A single mini PC with 64GB RAM + Ryzen 9 (~$700) can run 35 Docker containers easily. That's $700 vs $9,575.
  • A used server (Dell R730, 128GB RAM, dual Xeon) on eBay is ~$400–$600. Runs 100+ containers.

But you lose:

  • Physical isolation (one kernel panic = everything down)
  • Hardware passthrough (no GPIO, no Wiimotes per node)
  • Portability (can't take one node with you)
  • The learning experience of managing a real cluster

🎯 When 35 Pis Makes Sense

✅ It makes sense if:

  • You want a physical, visible, hands-on lab — for learning, teaching, or demonstrating
  • You need hardware isolation — each node has its own GPIO, USB, Bluetooth
  • You want to build a portable cluster — for demos, conferences, or field work
  • You're building a product that needs physical distribution
  • You want to learn distributed systems the hard way (which is the best way)

❌ It doesn't make sense if:

  • You just want to run 35 containers
  • You need high availability with a single point of management
  • You're optimizing purely for cost per CPU cycle

🔧 Recommended Build Path

If you're serious about 35 nodes, here's the order I'd do it in:

1 Start with 3–5 Pis

Prove your automated build process works end-to-end before committing to 35.

2 Build the first-boot SD card image

Each node reads a config file from /boot/firmware/winejs.conf and self-configures via a systemd unit. No SSH, no prompts, no manual steps.

3 Write an Ansible playbook

Push updates, new apps, and config changes to all nodes from your Mac with one command.

4 Set up monitoring before scaling

Prometheus + Grafana + node_exporter on all nodes. You need to see failures before they cascade.

5 Only then buy the rest

Once the process is solid and you've rebuilt a few nodes from scratch, scale to 35.
