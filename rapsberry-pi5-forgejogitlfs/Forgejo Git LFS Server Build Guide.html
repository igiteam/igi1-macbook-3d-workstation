🖥️ Headless Install — No Monitor, No Keyboard

You write the OS and your settings to the SD card on your Mac, insert it into the Pi, power on, and that's it. The Pi reads your pre-configured settings on first boot, connects to Wi-Fi, and enables SSH.

Yes — SD card on Mac, then insert and go

Everything is pre-configured on the SD card. No monitor or keyboard is ever needed. The Pi comes up on your network and waits for an SSH connection.

🛠️ Step 1: Pre-Configure on Your Mac

1 Install Raspberry Pi Imager

Download and install Raspberry Pi Imager on your Mac. Insert your microSD card using a card reader.

2 Choose Device and OS
  • Choose Device: Select "Raspberry Pi 5".
  • Choose OS: Go to "Other general-purpose OS" > Ubuntu > Ubuntu Server 24.04 LTS (64-bit). Do not pick the Desktop version.
  • Choose Storage: Select your SD card. Double-check you picked the right drive.
3 Open the Settings Menu

Click Next. When the popup asks about applying customisation, click "Edit Settings". (On some versions, press Ctrl+Shift+X.)

🔑 Step 2: Fill in the Settings

4 General Tab
  • Hostname: Give it a name, like forgejo-pi or winejs. This becomes its address on your network (forgejo-pi.local).
  • Username/Password: Set a custom username and a strong password. There is no default pi user anymore.
  • Wireless LAN: Enter your Wi-Fi SSID, Password, and Country. The country code is mandatory; the Pi won't turn on Wi-Fi without it.
  • Locale: Set your timezone.
5 Services Tab
  • Enable SSH: Check this box. Choose "Allow public-key authentication only" if you have an SSH key, or "Use password authentication" for simplicity. You absolutely must enable this, or you will have no way to log in.
6 Save and Write

Click Save, then Yes to apply the settings and write the image to the SD card. Wait for it to finish and eject the card.

🚀 Step 3: Boot and Connect

7 Power On

Insert the SD card into your Raspberry Pi 5. Power it on. It will take a minute or two to boot and connect to the network for the first time.

8 Find Its Address
  • Best way: Open a terminal on your Mac and try ssh username@forgejo-pi.local. The .local suffix uses mDNS, which usually just works on Macs and Linux.
  • Fallback: Log into your router's admin page and look for a "DHCP Client List" to find the IP address assigned to the Pi. Then run ssh username@<that-ip-address>.
9 Log In

The first time you connect, it will ask you to accept a fingerprint. Type yes, then enter the password you set in Step 2.

🖥️ Optional: Graphical Desktop via VNC

You don't need a monitor, but if you ever want to see a desktop GUI remotely, you can enable VNC after you're logged in via SSH. Run sudo raspi-config, go to "Interface Options" > "VNC" > "Enable". Then use a VNC viewer app on your Mac to connect to forgejo-pi.local.

🔌 NVMe Boot and Firmware

Modern Pi 5 units boot from NVMe out of the box

Raspberry Pi has shipped newer bootloader firmware since late 2024 that supports NVMe boot natively. If you bought a recent Pi 5, it likely already boots from NVMe without any update.

If your Pi 5 is from an old batch, you may need to update the bootloader. The easiest way is to flash Raspberry Pi OS to a temporary microSD card, boot it once with a monitor and keyboard attached, run sudo rpi-eeprom-update, then shut down. After that, the Pi will boot from NVMe headless forever.

You plug it in, it boots headless, you SSH in once, run your installers, and then it just sits there serving your projects. If you want it reachable from outside, add Tailscale (free for personal use) and you get a stable https://forgejo-pi.tailnet-name.ts.net URL without touching your router.

🔁 Reusable Build Notes (Multi-Server)

  • Standardise on Ubuntu Server 24.04 LTS (64-bit) for every node.
  • Enable dtparam=pciex1_gen=3 in /boot/firmware/config.txt if the NVMe drive needs it.
  • Run Forgejo via Docker Compose with LFS_START_SERVER = true.
  • Mount the NVMe SSD as the Forgejo data volume so repositories and LFS objects live on fast storage.
  • Set ROOT_URL to the node's IP or hostname (e.g. http://forgejo-01.local:3000/) — never localhost.
  • Use SQLite for a single-user instance; move to PostgreSQL if you scale up.
  • Set up a nightly rsync backup of the data volume to an external target.
